# ShopHot

面向速卖通（AliExpress）等海外电商卖家的商品分析与运营工具网站。第一版采用 **Python 3.12+ / Django 5.2 / SQLite / HTMX / ECharts**，无需安装 Node.js、Redis 或单独的数据库服务。

本地接续开发请先阅读 [交接文档 HANDOFF.md](HANDOFF.md)，其中包含启动、采集实测、代码入口及后续任务。

## 第一版功能

- 首页选择速卖通或 Shopify，输入竞品完整链接，自动加入采集队列，成功后识别名称并展示公开数据分析摘要。
- 登录保护的商品列表与详情，添加、编辑商品，按商品、店铺、平台和最新币种筛选。
- 多件竞品按同币种、同观测窗口对比价格曲线与公开评分；支持手动记录真实页面数据和报价条件。
- CSV 导入历史价格：全量校验、出错回滚、重复数据更新、空销量保留为未知。
- 按币种展示历史价格图表、首尾变化率与分页快照，导出筛选商品的全部历史。
- 独立采集进程、数据库任务队列、状态查看、失败原因、手动重试与中断任务恢复。
- 速卖通公开页面 JSON-LD 价格采集；记录观测时间与来源，不覆盖历史，不猜测销量。
- 单件利润估算：手动汇率、采购成本、运费、平台费率和其他成本。
- Django 管理后台、轮转日志、明确标注的可重复加载演示数据。

**范围限制：** 尚未接入速卖通官方 API；页面采集需要目标返回含明确价格的 JSON-LD。需要登录、动态加载、访问验证、价格区间或多个规格时会失败并显示原因，不绕过验证。Shopify 支持公开 Ajax 商品接口，需明确规格；其他平台支持 CSV 数据导入。首版为个人或可信小团队的共享工作台，所有登录账号共享商品数据，未实现租户隔离、自动选品或实时汇率。

Linux/macOS，在仓库目录运行：

```bash

.venv/bin/python manage.py createsuperuser
# 可选：加载虚构演示商品，重复运行不会增加重复记录

```

浏览器打开 `http://127.0.0.1:8000`，使用自己创建的账号登录。脚本同时启动网页和一个采集进程；按 Ctrl+C 停止。启动脚本使用 Django 开发服务器，仅用于本地开发。


## 使用流程

1. 在“商品分析”添加商品，填写名称、链接、平台和店铺；速卖通平台填写 `AliExpress`。
2. 有已有数据时，到“导入数据”下载表头模板，填写后上传；仓库 `examples/products.csv` 是虚构示例。
3. 查看商品详情，通过币种切换查看价格趋势和快照。
4. 使用速卖通公开商品链接时，点击“采集最新价格”；采集进程约每 2 秒检查队列，页面约每 3 秒检查任务是否完成。
5. 采集失败后查看任务说明，可以改用 CSV，或修正链接后重新采集。队列等待通常表示采集进程尚未运行。
6. 在列表页导出筛选商品的历史，或打开“利润工具”估算成本。

演示商品链接指向 `example.com`，不能进行速卖通采集。演示数据不是实际市场数据。

## CSV 格式

```csv
title,url,platform,shop,price,currency,sales,observed_at,source
示例商品,https://example.com/item/1,Other,示例店铺,19.90,USD,,2026-10-01T10:00:00+08:00,csv
```

- 必填 `title,url,price,currency,observed_at`，其他列可省略。表头不能有重复或空白字段。UTF-8 编码，支持 BOM，最大 2 MB / 5000 行。
- 币种为三个英文字母；价格非负、最多两位小数；销量未知留空。
- 时间使用 ISO 8601，推荐包含时区；无时区按 `Asia/Shanghai` 解释。图表与快照表统一使用该时区，不随浏览器时区改变。
- 商品按链接识别。重复导入会更新名称、平台、店铺，保留备注。
- 快照按“商品 + 观测时间 + source”去重；同键导入会更新价格、币种和销量。
- source 默认 `csv`，支持 `web`、`manual` 和 `demo`，用于保留导出来源。这是用户提供的来源标签，不代表平台认证。
- 导出会在可能被表格软件执行为公式的文本前加单引号；这类文本重新导入时会保留该引号。
- 可选 `rating`（0–5、最多两位小数）、`review_count`（非负整数）和 `context`（最多 300 字报价条件）；旧 CSV 文件无需新增这些列。
- 不同币种不合并计算变化率；图表最多展示所选币种最近 500 点，导出不受该限制。

## 采集与定时更新

网页请求只创建任务，网络请求在采集进程内执行，默认只运行一个 worker，避免 SQLite 写入竞争。

```bash
# 把所有 AliExpress 商品加入队列，已有活动任务不会重复加入
.venv/bin/python manage.py queue_products
# 处理当前队列后退出
.venv/bin/python manage.py collect_worker --once
# 持续运行
.venv/bin/python manage.py collect_worker
```

可用系统定时任务调用 `queue_products`。如果没有常驻 worker，再串行执行 `collect_worker --once`；不要安排多个重叠的 worker。命令使用仓库绝对路径或先切换到仓库目录。中断任务超过 10 分钟会在下次 worker 检查时标记失败，用户可以重新加入队列。

网络需允许 `aliexpress.com` 和 `*.aliexpress.com` 的 HTTPS 访问。安装依赖使用 `pypi.org`、`files.pythonhosted.org`。即使网络允许，目标网站也可能要求登录或拒绝自动访问。请仅采集自己有权访问的数据，优先使用官方接口、授权数据或 CSV。

## 配置、日志和备份

- 默认数据库为仓库内 `db.sqlite3`，日志为 `logs/shophot.log`，最大 2 MB、保留 3 个备份；这些文件均不提交 Git。
- 日志包含导入数量、任务 ID、执行结果和可公开的失败原因，不记录账号密码、Cookie 或完整页面正文。
- 环境变量示例见 `.env.example`，配置读取进程环境；文件不会自动加载。可在环境设置、shell 或进程管理器中设置。
- 默认仅监听本机。正式部署需设置 `SHOPHOT_DEBUG=0`、独立随机 `SHOPHOT_SECRET_KEY`、允许域名和 HTTPS CSRF 来源，并使用正式 WSGI 服务与 HTTPS；开发服务器不是生产部署方案。
- 备份前停止网页和 worker，再复制 `db.sqlite3` 到仓库外的安全位置；恢复时停服替换数据库并运行 `migrate`。不要把个人数据或密钥推送 Git。
- 当多人使用或并发采集增加时，再迁移到 PostgreSQL、Celery/Redis；本版不需要这些组件。

### 竞品分析流程

首页输入完整速卖通商品链接，例如 `/item/商品编号.html`，点击“开始分析”。网站会去除标准商品链接的营销参数，按商品 ID 跟踪，创建采集任务并打开报告页面。成功后展示识别到的名称、明确价格、五分制评分和公开评价数；首次采集只有一个观测点，不会生成虚构历史趋势。

“竞品对比”可选择 2–8 件商品，按币种和最近 7 / 30 / 90 天或全部历史对比。不同商品的采集时间、规格、折扣、税费和运费可能不同，对比表展示观测时间与报价条件，不把公开评价数当作订单数。每条曲线最多 500 点，价格变化率按整个筛选窗口计算。

若自动采集失败，报告会保留失败原因；已有历史仍可查看。“记录公开数据”可以保存你实际在商品页面看到的价格、评分、评价数、公开销量与报价条件，来源固定为 `manual`，不伪装成自动采集。相同商品、观测时间的手动记录重复提交会更新原记录。

页面采集优先按 JSON-LD 的商品编号识别目标，无法分辨多个商品时明确失败，不把推荐商品价格用于目标竞品。尚未接入完整动态页面采集或官方授权接口，代理 403 阻塞期间，自动分析入口可用不代表真实数据采集已成功。

用 `--artifacts /tmp/shophot-selfcheck-artifacts` 可保存详情和手机截图。脚本覆盖登录与退出、商品添加编辑、真实 worker 的失败反馈、CSV 错误提示和重复导入、导出、HTMX 利润计算，竞品对比、手动公开观测，以及美国浏览器时区下的图表一致性。自动分析使用 `examples/fixtures/competitor_product.html` 受控测试夹具，不请求该示例商品，不证明实站采集成功。截图和测试产物请保存在仓库外。单元测试不需要安装 Playwright。

## v0.2：Shopify 与研究工作台

- 首页选择 Shopify，粘贴 HTTPS `/products/handle` 商品链接；支持自定义域名、语言路径与集合路径。营销参数会被移除，`variant`、`currency`、`country` 保留。
- 多规格商品必须使用带 `?variant=编号` 的链接；单规格自动识别。不同规格链接分别跟踪，不合并成同一商品历史。
- 读取公开 `/products/handle.js` 和 `/cart.js`；价格使用 Shopify 接口的百分之一单位，币种以实际 cart 响应为准，指定币种不一致则失败。每次任务使用独立客户端，不代表某个登录用户的折扣或市场报价。
- 记录规格编号、名称及报价条件；运费、税费、国家是否生效未确认。价格曲线仍按币种筛选，市场条件需结合快照备注阅读。
- 不读取商家后台；销量、营收、库存数量和广告花费不会由这些接口推算。密码保护、跳转或非 JSON 响应会明确失败。
- `/stores/` 按 Shopify 域名或速卖通店铺名汇总已跟踪商品；这些是样本数，不代表店铺完整目录。域名别名尚未合并。
- `/collections/` 集中查看任务、按状态筛选并重试失败任务。`queue_products` 同时支持两个平台；没有自动定时调度。
- 桌面侧栏与移动布局已更新。macOS Bash 3.2 可运行 `scripts/start.sh`。

Shopify 网络请求固定到 DNS 检查得到的公网 IP，同时保留域名 Host、TLS 证书校验与域名 Cookie；不跟随重定向，不使用环境代理。如果本机代理仅返回 `198.18.0.0/15` Fake-IP，使用 Cloudflare HTTPS DNS 查询真实地址，再检查公网属性并固定连接。私网和混合地址仍拒绝；不修改系统代理或 DNS。限流尊重 Retry-After，最多延迟重试一次。

接口依据：[Shopify Product Ajax API](https://shopify.dev/docs/api/ajax/reference/product)。

## 利润工具更新

可选择销售币种和成本币种，跨币种手动输入汇率；支持折扣、采购、物流、广告、其他成本及支付固定费/比例费。展示净利润、利润率、ROI、保本成交价和目标利润率成交价。切换币种要求重新确认汇率，修改参数会提醒旧结果待更新。它是成本假设模型，不代表竞品实际利润。

物流支持直接填实际单件运费，或选择报价填写整包重量、尺寸、附加费、汇率和同款件数。`/tools/logistics/` 可管理私有报价、下载 Excel/CSV 模板、校验预览并确认导入；支持每公斤与首重续重规则、体积重、燃油基数及分摊尾差。公开参考为顺丰官方 2026 国际特惠 8 条线路的 0.5–5 kg 公布包裹价，非货代协议价，附加费仍须核实。详见 [SHIPPING_MODULE.md](SHIPPING_MODULE.md)。

利润采用统一两位金额核算：折后价、换算收入和比例费用分别四舍五入，总成本直接相加页面分项，净利直接相减。定价建议在同一舍入口径下反算并验算达标。实际合同若按其他币种或舍入口径收费，先核对合同再使用，不自动推断税费或实时汇率。

真实验证与速卖通接口申请见 [LIVE_VALIDATION.md](LIVE_VALIDATION.md)、[ALIEXPRESS_API.md](ALIEXPRESS_API.md)。

## 公开店铺目录与 PostgreSQL

`/stores/` 现在可以输入 Shopify 店铺首页，后台发现公开 sitemap 商品链接并保存带时间的目录结果。最多 100 件、3 个商品子地图；截取会显示提示，未返回不表示下架。已实测 LILYGO 目录成功。价格与规格需另行观测，目录不代表订单数据。

数据来源研究见 [DATA_SOURCES.md](DATA_SOURCES.md)，数据库配置与启动见 [DATABASE.md](DATABASE.md)。本机数据库切换使用独立 PostgreSQL 17 集群；没有 `.local/database.json` 的其他环境仍可使用 SQLite。

工作台入口默认“自动识别链接”，可以直接粘贴 `https://millys.co.uk/` 这类自定义域名首页。首页会排队发现公开目录；商品 `/products/…` 链接继续进入价格观测。首页任务不会创建一条没有商品身份的 Product 记录。自动识别仅决定尝试的采集路径，接口结果才确认数据可用。

### 店铺公开报价（第一步）

店铺研究页可采集目录前 10 件商品的公开 HTML 报价，显示原币种、多规格报价范围、页面库存标注、来源链接与 UTC 观测时间。报价保存在 PostgreSQL；未取得的价格保持未知。支持分批续采已发现目录，并记录新观测的独立报价历史；价格趋势图和定时更新尚未实现。

额度不足或恢复工作时，先读 [开发续接日志](DEVELOPMENT_LOG.md)。

报价现支持下一批、连续采集剩余商品、失败商品重试和全目录重新观测（目录最多 100 件、内部每批最多 10 件）。成功报价保存独立 `CatalogPriceObservation` 历史；店铺页显示覆盖率与最近 10 条历史报价。网络拒绝或限流会停止本次任务，保留已取得结果，用户可稍后手动续采。

### 词条与商品关系

侧栏“词条研究”使用真实目录商品标题统计商品覆盖次数，支持词条和报价币种筛选。交互树将每件商品按标题中的高频词归组：点击词条圆点筛选，点击商品圆点定位公开报价。词条覆盖不等于搜索量、热度或销量；关系树不是店铺官方分类。暂无评价主题分析或中文语义分词。

### 公开商品详情与真实评价

店铺目录和词条研究列表可进入商品详情，展示最多 6 张公开图片、纯文本原描述、品牌/页面品类/SKU、逐规格公开报价与库存、标题词条和最近报价历史。“更新当前商品”只将该目录商品排队更新，不必重复采集全店。内容随成功报价观测保存；失败时保留旧数据与原观测时间。

商品评分、评价数、评分人数与评论样本独立展示。汇总来自匹配商品 JSON-LD；评论可读取目标商品 JSON-LD 或公开页面已嵌入且明确归属商品的 Judge.me 组件，最多 10 条。暂无全量评价采集和主题统计，未知值明确显示。已实测 Beardbrand 三件商品；Millys 混合店铺评价不作为商品评价。

### 商品筛选与价格分布

词条研究页可按标题包含、精确词条、单币种价格范围、最低评分和评价数筛选，并按标题、最低报价、评分或评价数排序。价格区间按规格报价范围与筛选范围重叠处理；价格筛选/排序须先选择币种。未知值不按零计入阈值，错误条件会明确提示。

价格分布对当前结果按最低公开价每商品计一次，各币种独立展示，提供文字计数。目录词条比例仍以整个目录为分母；商品表直接展示明确评分与评价数。分布不是成交价或销量分布。

### 跨店商品研究与公开对比

“商品研究”汇总最近最多 30 家店铺各自最新成功目录，支持跨店标题/词条/价格/评分/评价数筛选排序和分币种最低报价分布，每页 50 件。目录可能截取，不能视为完整市场。

当前页可勾选 2–8 件有有效公开报价的同币种商品，显示报价上下限、库存、评分/评价数、已取得规格条数、观测时间与来源。不同币种、未知报价、重复商品或无效选择会被拒绝。它比较页面报价范围，不将不同规格条件混为成交价，不生成历史走势。原有 Product/Snapshot 竞品历史对比保持独立。


### 商品评论样本分析

商品详情的评价区提供已取得评论的评分分组、高频词图、关注点、明确正面表述与待核实的问题线索，均可定位原评论。每词按评论覆盖数统计，去重并去除常见停用词，最多分析 10 条。当前为本地规则、有限英文词形归并及常见中文词匹配，可能漏识别复杂表达；高评分中的不足单独保留。没有有效商品评论时不生成分析，不把样本分布当全部评价或整体质量结论。


### 库存、数据覆盖筛选与 CSV 导出

商品研究和店铺词条研究可筛选公开库存状态、有/无有效报价、有/无有效评论样本、最近采集失败及尚未采集报价。库存来自保存时的公开状态，不是实时库存；评论样本数最多 10 条，不等于完整评价数。

跨店商品研究可导出当前全部匹配结果（包含所有页且保留排序）。CSV 使用 UTF-8 BOM，含报价、币种、库存、评分/评价数、样本覆盖、来源、时间、错误与截取标记。未知数字留空、零值保留；导出不重新采集。非法筛选无法导出。


### 个人候选商品清单

商品研究及商品报告可收藏到「候选清单」。每个账号独立，按商品链接去重，可记录最多 2000 字备注并标记研究中/重点关注/暂不考虑，支持搜索和状态筛选。移出后可以恢复，重复收藏保留备注。

重新采集店铺后按链接关联最新目录，商品排序改变不会错位；最新截取目录缺少商品时保留收藏时数据并明确提示，不能视为下架。原目录删除不会删除收藏。清单不自动联网刷新，进入商品报告可手动更新。

可勾选 2–8 件有有效报价且在最新目录的同币种候选商品进行公开对比；仍需确认商品和规格是否可比。新增迁移 `0006_catalogcandidate`，运行 `bash scripts/start.sh` 会自动应用。


### 分析首页与连续报告流程

首页默认自动识别链接。已保存的店铺/商品可直接打开对应报告；新店铺先显示进度，目录发现后自动分析首批最多 10 件商品，再进入店铺报告。商品采集成功自动进入报告，失败显示原因与重试入口。无需在侧栏寻找本次结果，进度页读取状态不会创建采集任务。

常用研究筛选直接展示，高级筛选与数据说明展开查看；店铺报告优先展示商品列表，图表可展开或通过报告导航定位。手机导航折叠为菜单。

### 后续按模块开发

开发约定见 [AGENTS.md](AGENTS.md)，模块地图、代码边界与验证步骤见 [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md)。公共 UI 由 `ui.css` / `ui.js` 与模板 partials 管理；分析流程由 `workflows.py` / `workflow_views.py` 管理。新功能优先使用独立模块，历史集中代码按实际修改范围逐步整理，不整仓重构。


### 目录商品报价历史分析

商品报告的「最近报价记录」可进入历史分析，跨店铺目录合并同一商品链接的成功观测，按币种与全部/30/90 天窗口查看，最多显示最近 500 条。

后续采集会记录对应公开规格范围。同币种且相同已记录范围的相邻观测才连线、计算报价上下限变化；旧记录缺少依据或范围变化时不推断涨跌。零基准不计算百分比。上下限不变不代表每条规格价格都未变，图的点按观测顺序排列，不表示实际时间间隔。失败不会补零或写入观测。本模块分析页面报价范围，不是具体规格成交价。

该模块使用 `price_history.py` / `price_history_views.py` / `price_history_forms.py`，迁移 `0008_catalogpriceobservation_quote_scope`。现有旧记录保持原样，不用当前规格回填历史。

## 定时价格监测（2026-10-08）

从目录商品报告选择“设置价格监测”，可设每 6 小时、每 12 小时或每天一次；在“价格监测”查看下次执行、最近结果、报价历史，暂停或恢复。计划按账号隔离，存入 PostgreSQL，由 `bash scripts/start.sh` 启动的现有单 worker 调度，不需要另装 Redis 或操作系统定时器。

首次开启及恢复后安排一次采集；成功后从本次完成时间起按频率安排，修改频率会调整尚未排队的下一次执行。相同目录的相同待采集目标共享任务，目录繁忙时延后 5 分钟；失败后按频率指数退避，最长 72 小时。商品以链接匹配，保留影响市场/规格的查询参数，目录重排不会换成另一个商品；新目录缺失时可使用仍保存的旧目录。公开页面返回访问限制时明确失败，不覆盖成功历史，不绕过验证。

目前仅覆盖已发现目录中的公开商品，尚不自动扫描全店或支持被访问验证拦截的速卖通商品。监测是定时采集，不是实时推送；队列繁忙时会晚于计划时间。电脑休眠或采集服务关闭时停止执行，恢复后只处理一次到期检查，不补造漏掉的历史。未配置系统开机启动或云端常驻服务，也尚未提供降价通知。

## 样本市场分析（2026-10-08）

在“商品研究”选择“样本市场分析”，或访问 `/research/market/`。读取最近最多 30 家店铺的最新成功目录，按商品链接去重；支持标题、店铺、币种、公开品牌和最低报价价格段筛选。图表及文字链接可直接筛出对应商品，再进入商品报告、评论或历史监测。

每个币种分别统计商品报价下限的分布、中位数及范围；品牌占比以当前匹配商品数量为分母，包含未知品牌。数据覆盖显示已知评分/评价数、真实评论样本、报价缺失、失败和 24 小时新鲜度，未知不补零。价格段筛选按报价下限而非规格范围相交；币种筛选会排除报价未知商品。品牌仅按公开名称忽略大小写合并。这里是自选店铺样本，不是平台全市场份额、成交价、销售额或搜索量。页面只读取数据，不发起采集。

跨平台真实验收见 [CROSS_PLATFORM_VALIDATION.md](CROSS_PLATFORM_VALIDATION.md)。SHEIN、OTTO、Ozon 目前仅识别并明确提示尚未接入，不能自动保存竞品价格或评价；速卖通店铺目录也未接入，不能把域名识别当成采集支持。
